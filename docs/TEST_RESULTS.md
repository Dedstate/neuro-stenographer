# Исправление 0.1.1 — ошибка dlopen на Android

Пользовательский запуск подтвердил: APK 0.1.0 не мог загрузить Sherpa JNI из-за `OrtGetApiBase@VERS_1.28.2` против runtime `VERS_1.28.0`. Предыдущая проверка наличия файлов не обнаруживала эту несовместимость.

Исправление: родной Sherpa ORT 1.28.2 + пересобранный официальный Java JNI 1.28.0; Java API не менялся. Проверка `check_apk.py` теперь отвергает старый APK именно по несовместимому ELF-символу.

Сборка 0.1.1: assembleDebug, assembleDebugAndroidTest, 13 JVM-тестов, lint (0 ошибок) — успешно. 6 Python-тестов — успешно. Проверены модельные хэши, подпись v2, отсутствие INTERNET, ELF-linkage обоих JNI для ARM64 и x86_64. Старый APK регрессионная проверка отвергает; новый проходит. Хэш/размер новой сборки — в artifacts/test-results/apk-build.json.

Ожидаемый повторный Android-тест: установить 0.1.1 и импортировать тот же WAV. Работа последующих этапов и показатели памяти ещё требуют проверки на устройстве.

- Android instrumentation APK скомпилирован, но не запущен: устройства и KVM в среде нет.
- Kotlin unit tests покрывают точный JSON-контракт, границы/сортировку спикеров, непрерывность ASR-нарезки, ресемплирование и anti-alias, WordPiece, метки RUPunct, WAV16 stereo/24-bit/float и повреждённый WAV.

## Диагностический CPU-инференс (не Android-бенчмарк)

До финальной Android-сборки выполнена диагностика весов на компьютере:

- Sherpa-ONNX 2.0.1: сегментация + embedding на командном `dialogue.wav`, 36.79 с, mono PCM16 16 kHz; затем GigaAM по найденным интервалам.
- Получены реальные русские реплики, включая «начинаем маршрут», «что для тебя» и длинные фрагменты диалога.
- Найдено 3 speaker ID, в том числе короткий ложный/сомнительный интервал и пересечения. Это **не подтверждение качества**. Есть склеенные фразы и ошибки ASR. WER/DER не вычислены: эталонной разметки нет.
- RUPunct INT8 действительно выполнила token classification: `привет коллеги` → метки `UPPER_COMMA` / `LOWER_VOSKL`; русский вопрос заканчивается `LOWER_QUESTION`. Тестировались 4 короткие фразы, не длинные стенограммы.
- CPU-диагностика RUPunct использовала Python ORT 1.31.1; это не финальный Android runtime. Время компьютера не переносится на телефон.
- Повторный полный CPU-запуск с ORT 1.31.1 был заблокирован автоматической проверкой из-за попытки обращения к телеметрии Microsoft. Он не засчитан как успешный. Android закреплён на ORT 1.28.0, телеметрия отключается явно; разрешение INTERNET отсутствует. Повторный CPU-запуск не выполнялся.
